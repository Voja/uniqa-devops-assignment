# Security

## What runs automatically

| Layer | Tool | Where | Gate |
|---|---|---|---|
| Infrastructure as Code | [Checkov](https://www.checkov.io/) | `CI` → `infra-quality` job, config in [checkov.yml](checkov.yml) | `soft_fail: false` — any un-skipped finding fails the build |
| Python code | [Bandit](https://bandit.readthedocs.io/) | `CI` (`-q`) and `QA` (full text report in the job summary) | non-zero exit fails the job |
| Terraform hygiene | `terraform fmt -check`, `terraform validate` | `CI` → `infra-quality` | fail on drift / invalid config |
| Code quality | flake8, black, pylint (`--fail-under=8`) | `CI` / `QA` | fail on violation |

Every Checkov skip in [checkov.yml](checkov.yml) carries a one-line justification. The list is deliberately
explicit: a reviewer can see exactly which production controls were traded for cost/scope in this demo.

## No secrets in the repository

- `.gitignore` excludes `*.tfvars` (except the committed, secret-free `envs/*.tfvars`), `*.tfstate*`,
  `backend.hcl`, `.env`, `*.pem`.
- Terraform secrets (`subscription_id`, `sql_server_name`, `sql_admin_password`) are passed as
  `TF_VAR_*` environment variables; the SQL admin password is generated by `random_password` and only
  ever lives in Terraform state (remote state in a private storage container).
- The app receives its SQL connection string from App Service **Connection Strings**
  (`SQLCONNSTR_TransactionsDb`), never from code or the zip package.
- The Flask session key (`SECRET_KEY`) is generated per environment by Terraform (`random_password`)
  and injected as an App Service app setting; the code has no hard-coded fallback (a random
  per-process key is used only when the variable is absent, i.e. locally and in tests).
- Pipelines read `secrets.AZURE_CREDENTIALS` (service principal JSON) and GitHub Environment
  variables; nothing sensitive is hard-coded in YAML.

## Service principal — least privilege

The deployment SP only needs to deploy code and change one app setting. Scope it to the shared
resource group with the built-in **Website Contributor** role (not Contributor on the subscription):

```bash
az ad sp create-for-rbac --name "sp-uniqa-github-deploy" \
  --role "Website Contributor" \
  --scopes "/subscriptions/<sub>/resourceGroups/rg-uniqa-shared" \
  --sdk-auth   # JSON for secrets.AZURE_CREDENTIALS
```

Terraform applies are run by an engineer (interactive `az login`), not by the pipeline, so the SP
never needs rights over the network, SQL or storage resources.

## Platform controls already in place

- HTTPS only, TLS 1.2 minimum, FTPS disabled, HTTP/2 on the Web App; TLS 1.2 minimum on SQL and storage.
- Private Endpoint for the Web App and the SQL Server, VNet Integration with `vnet_route_all_enabled`.
- SQL public endpoint restricted to a single admin IP via firewall rule.
- System-assigned managed identity on the Web App (ready for RBAC-based access, no secrets).
- Bandit-reviewed code: parameterised SQL everywhere, input validation on `POST /transactions`.

## What would be added for production

1. **OIDC federated credentials** for GitHub Actions (`azure/login` with `client-id`/`tenant-id`,
   `permissions: id-token: write`) — removes the long-lived client secret entirely.
2. **Key Vault references** for the connection string
   (`@Microsoft.KeyVault(SecretUri=...)`) or, better, **Azure AD / managed-identity auth** to SQL so
   there is no password at all (also clears Checkov `CKV2_AZURE_27`).
3. **Microsoft Defender for Cloud** (Defender for SQL, App Service, Storage) plus SQL auditing to
   Log Analytics — clears `CKV_AZURE_23/24/25`, `CKV2_AZURE_2`.
4. **Private SCM / deployment path**: `public_network_access_enabled = false` on the Web App, deploy
   from a self-hosted runner inside the VNet (or a private endpoint for the `scm` subresource), and
   front ingress with Application Gateway / Front Door + WAF — clears `CKV_AZURE_222`.
5. **Storage hardening** for the tfstate account: soft-delete + versioning, deny-by-default network
   rules with a private endpoint, shared-key auth disabled (Azure AD auth for the backend) — clears
   the `CKV2_AZURE_3x/4x` group.
6. NSGs on both subnets, zone-redundant Premium plan, SQL tier with zone redundancy.
