# Transactions API

Small Flask app exposing a health endpoint and a simple transactions API.
Uses Azure SQL (via pymssql) when a connection string is set, otherwise an in-memory SQLite DB.

## Run locally
    python -m venv .venv && . .venv/bin/activate
    pip install -r requirements-dev.txt
    python app.py            # http://localhost:8000/health

## Tests
    pytest --cov=.

## Routes

| Route | Purpose |
|---|---|
| `GET /` | Operations console UI (request path, stats, add form, latest transactions, runtime) |
| `POST /transactions/form` | HTML form handler; validates, inserts, redirects to `/` with a flash message |
| `GET /health` | Liveness probe: `{"status","env","version"}` (used by App Service health check and CD smoke tests) |
| `GET /health/deep` | Dependency probe: `SELECT 1` timing → `{"status":"ok"\|"degraded","db":{...}}` |
| `GET /transactions` | Last 20 transactions as JSON |
| `POST /transactions` | Create from JSON `{"amount": number, "description": string}` → 201, or 400 |

## Environment variables
- `APP_ENV` (default `local`), `APP_VERSION` (default `0.0.0`), `PORT` (default `8000`)
- `SECRET_KEY` – signs the session cookie used for UI flash messages. On App Service it is an app setting
  generated by Terraform (`random_password`, per environment) and never stored in the repo. When unset
  (local runs, tests) the app generates a random per-process key, so there is no hard-coded fallback.
- Read-only, shown in the UI when present: `WEBSITE_HOSTNAME`, `WEBSITE_SITE_NAME`, `WEBSITE_PRIVATE_IP`,
  `WEBSITE_INSTANCE_ID`, `REGION_NAME`, `LOG_LEVEL`, `FEATURE_FLAG_DEMO`.
- `SQLCONNSTR_TransactionsDb` – ADO.NET-style SQL Server connection string (App Service connection string
  "TransactionsDb"). Parsed and passed to `pymssql`, which ships as a self-contained wheel — no OS-level
  ODBC driver is needed on the App Service Linux image. Unset = in-memory SQLite (local runs and tests).
